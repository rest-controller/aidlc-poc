# User Stories Planning Questions

Story format: "As a [persona], I want [goal], so that [benefit]", written to the INVEST checklist (Independent, Negotiable, Valuable, Estimable, Small, Testable), with Given/When/Then acceptance criteria. Each story gets a priority (Must Have / Should Have / Could Have / Won't Have). The requirements are already settled, so only three planning choices remain.

## Q1. [Product] Who are the people the stories are about?

A. One persona, a "Visitor" who signs up and later logs in
B. Two personas: a "New visitor" who signs up and a "Returning user" who logs in (the demo user counts as a returning user)
C. Three personas: "New visitor", "Returning user" and "Demo user" kept separate
X. Other (please specify)

[Answer]: B

## Q2. [Product] How should the stories be split up?

A. By workflow step: sign up, get a clear error, reach the page, log in as a registered user, keep the demo user working
B. By screen: sign-up page stories, login page stories
C. By requirement group (FR1 to FR7), one story each
X. Other (please specify)

[Answer]: A

## Q3. [Product] Which stories are must-haves?

A. Everything is Must Have except the page-to-page links, which are Should Have
B. Everything is Must Have
X. Other (please specify)

[Answer]: A
